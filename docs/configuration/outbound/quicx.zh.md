### 结构

```json
{
  "type": "quicx",
  "tag": "quicx-out",

  "server": "127.0.0.1",
  "server_port": 1080,
  "password": "hello",
  "idle_timeout": "",
  "heartbeat": "",
  "mtu": 0,
  "fec": {},
  "network": "",

  ... // 拨号字段
}
```

### 字段

#### server

==必填==

服务器地址。

#### server_port

==必填==

服务器端口。

#### password

==必填==

quicx 用户密码。

#### idle_timeout

连接空闲超时时间

默认使用 `30s`。

#### heartbeat

发送心跳包以保持连接存活的时间间隔

默认使用 `10s`。

#### mtu

本端发出的包的最大长度，`1200` 到 `1452`。

默认为 `0`，即自动探测：连接建立后按地址族的默认值（IPv4 为 `1452`，IPv6 为 `1232`）发一个探测包，没有应答就退到下一档（`1400`、`1280`、`1200`），最多探测四次。探测包不占拥塞窗口，也不重传。

路径大小已知时填写它，探测就省下了。

#### fec

前向纠错，保护本端发出的包。

客户端发出的是请求，服务端发出的是应答，所以这一项只覆盖请求方向；两个方向都要保护时，入站与出站都要配置。冗余包与数据包一样占拥塞窗口，因此它不会让链路更拥塞，只会把一部分带宽换成无需重传的恢复。

被冗余修复的包会按丢包上报给拥塞控制：数据到了，但路径确实丢了它，发送速率会因此降下来。这是有意的取舍——用冗余换到的不是"当没发生过"，而是"不用重传，但少发一点"。

```json
{
  "fec": {
    "enabled": true
  }
}
```

#### fec.enabled

==必填==

开启前向纠错。未开启时不能填写 `data_shards` 与 `parity_shards`。

#### fec.data_shards

一组包含的包数，`2` 到 `32`。

默认为 `32`。组越宽，冗余占的比例越小；覆盖 TCP 时 `32+2` 的尾延迟与带宽开销都优于 `10+2`。

#### fec.parity_shards

一组附带的冗余包数，`2` 到 `8`，且不超过 `data_shards`。

默认为 `2`。

#### network

启用的网络协议。

`tcp` 或 `udp`。

默认所有。

### 拨号字段

参阅 [拨号字段](/zh/configuration/shared/dial/) 了解详情。

### 说明

quicx 不是 QUIC：它运行在自己的 UDP 传输层上，不使用 TLS 与 HTTP/3，因此没有证书、ALPN、qlog 与 QUIC 相关配置项。
